# Конфигурация

Настройки и пресеты хранятся в TOML-файле. Обычно его редактирует окно программы; ручная правка допустима (перезапустите программу, чтобы она перечитала файл).

## Расположение

| Файл | Путь | Назначение |
|---|---|---|
| `config.toml` | `%APPDATA%\PresetLauncher\config.toml` | настройки и пресеты |
| `state.toml` | `%APPDATA%\PresetLauncher\state.toml` | активный пресет (пишет только движок) |
| `launcher.log` | `%APPDATA%\PresetLauncher\launcher.log` | журнал; при размере больше 1 МБ переименовывается в `launcher.log.old` |
| `config.toml.broken` | там же | копия повреждённого конфига |

Каталог можно переопределить переменной окружения `PRESET_LAUNCHER_DIR` (для переносной установки и тестов).

Если `config.toml` нет, при первом запуске создаётся конфиг по умолчанию («Работа» и «Игры») из программ, найденных на ПК. Если файл существует, но не читается, он копируется в `config.toml.broken`, загружаются пресеты по умолчанию, а ошибка пишется в журнал. Запись конфига атомарная (через временный файл).

Все поля необязательны: отсутствующее принимает значение по умолчанию.

## Секция `[settings]`

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `close_timeout_secs` | целое >= 0 | `10` | сколько ждать мягкого закрытия программ, прежде чем завершить их принудительно (если `force_kill = true`) |
| `startup_preset` | строка | `""` | пресет, применяемый при запуске с `--autostart`; пусто - не применять |
| `api_enabled` | bool | `false` | включить HTTP API |
| `api_port` | целое 0-65535 | `47800` | порт API |
| `api_token` | строка | `""` | Bearer-токен. Пустой при включённом API - создаётся автоматически (32 случайных байта в hex) |

## Пресеты `[[preset]]`

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `name` | строка | `""` | имя пресета (используется в меню трея и API); должно быть уникальным |
| `app` | массив таблиц `[[preset.app]]` | `[]` | программы пресета, в порядке запуска |

## Программы `[[preset.app]]`

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `enabled` | bool | `true` | выключенная программа не запускается и не закрывается |
| `name` | строка | `""` | отображаемое имя; пусто - имя файла без расширения |
| `path` | строка | `""` | путь к `.exe` или всё, что открывает ShellExecute (`.lnk`, URL, `steam://...`). Переменные `%VAR%` раскрываются |
| `args` | строка | `""` | аргументы одной строкой, передаются как есть (пути с пробелами заключайте в кавычки сами); `%VAR%` раскрываются |
| `working_dir` | строка | `""` | рабочий каталог; `%VAR%` раскрываются |
| `process_name` | строка | `""` | имя образа процесса для поиска и закрытия (например `Discord.exe`). Пусто - имя файла из `path`; для URL и не-`.exe` без этого поля процесс не отслеживается |
| `delay_ms` | целое >= 0 | `500` | пауза после запуска этой программы, до следующей |
| `launch_if_running` | bool | `false` | запускать, даже если процесс уже запущен (например браузер с рабочими вкладками) |
| `close_on_switch` | bool | `true` | закрывать при переключении на пресет, в котором этой программы нет |
| `force_kill` | bool | `true` | завершить процесс принудительно, если он не закрылся за `close_timeout_secs` (или сразу, если у него нет окон) |
| `close_command` | строка | `""` | командная строка для закрытия вместо `WM_CLOSE`, например `"C:\Program Files (x86)\Steam\steam.exe" -shutdown` |

### Как работает переключение

1. Из всех **других** пресетов выбираются включённые программы с `close_on_switch = true`. Исключаются те, чей процесс используется включённой программой целевого пресета, и системные защищённые процессы.
2. Каждой из них отправляется `WM_CLOSE` (или выполняется `close_command`). Ожидание длится до `close_timeout_secs`. Приложения, которые после `WM_CLOSE` скрылись в трей (остались без видимых окон дольше 3 с), при `force_kill = true` завершаются сразу.
3. Не закрывшиеся к таймауту завершаются принудительно при `force_kill = true`, иначе остаются работать.
4. Программы целевого пресета запускаются по порядку. Уже запущенные пропускаются, если не задан `launch_if_running`. После каждого запуска - пауза `delay_ms`.
5. Новая команда переключения прерывает текущее переключение; промежуточные команды в очереди отбрасываются.

## Пример

```toml
[settings]
close_timeout_secs = 10
startup_preset = "Работа"
api_enabled = true
api_port = 47800
api_token = "замените-на-случайную-строку"

[[preset]]
name = "Работа"

[[preset.app]]
name = "Браузер (рабочие вкладки)"
path = "C:\\Program Files\\Google\\Chrome\\Application\\chrome.exe"
args = "--new-window https://github.com"
launch_if_running = true

[[preset.app]]
name = "Терминал"
path = "wt.exe"
args = "-d \"%USERPROFILE%\""
process_name = "WindowsTerminal.exe"

[[preset]]
name = "Игры"

[[preset.app]]
name = "Discord"
path = "%LOCALAPPDATA%\\Discord\\Update.exe"
args = "--processStart Discord.exe"
process_name = "Discord.exe"

[[preset.app]]
name = "Steam"
path = "C:\\Program Files (x86)\\Steam\\steam.exe"
close_command = "\"C:\\Program Files (x86)\\Steam\\steam.exe\" -shutdown"
delay_ms = 1000
```

Безопасность токена: не публикуйте `config.toml` с заполненным `api_token`.
