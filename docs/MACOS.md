# Preset Launcher на macOS

Версия 0.5.0 работает и на macOS 12+ (Apple Silicon и Intel). Интерфейс, пресеты, трей (значок в строке меню), горячие клавиши и HTTP API те же, что в Windows-версии. Ниже - что отличается.

> Порт собирается и проверяется на Windows (компиляция и clippy под `aarch64-apple-darwin`) и в GitHub Actions на `macos-latest`. Часть системных вызовов нельзя проверить без настоящего Mac, поэтому, если что-то из списка ниже не работает, пожалуйста, пришлите запись из журнала.

## Установка

1. Скачайте `PresetLauncher-<версия>-macos.zip` со страницы релиза и распакуйте.
2. Перетащите `Preset Launcher.app` в «Программы».
3. Приложение **не подписано сертификатом разработчика** (только ad-hoc-подпись), поэтому при первом запуске macOS его заблокирует. Разрешить можно так:
   - правый клик по приложению → **Открыть** → **Открыть** в диалоге; или
   - в Терминале: `xattr -dr com.apple.quarantine "/Applications/Preset Launcher.app"`.
4. В строке меню появится значок. Левый клик открывает окно, правый - меню с пресетами.

Собрать самому (на Mac, нужны Rust и Xcode Command Line Tools): `bash scripts/bundle-macos.sh`. Результат - `dist/Preset Launcher.app` и zip. Скрипт собирает universal-бинарник (arm64 + x86_64), если у `rustup` есть обе цели.

## Где что лежит

| Что | Путь |
|---|---|
| конфиг пресетов и настроек | `~/Library/Application Support/PresetLauncher/config.toml` |
| активный пресет | `~/Library/Application Support/PresetLauncher/state.toml` |
| журнал | `~/Library/Application Support/PresetLauncher/launcher.log` (+ `.old`) |
| блокировка единственного экземпляра | `…/PresetLauncher/instance.lock` |
| автозапуск | `~/Library/LaunchAgents/io.github.eg0rs.presetlauncher.plist` |

Переменная `PRESET_LAUNCHER_DIR` по-прежнему переопределяет каталог конфига. Формат `config.toml` описан в [CONFIG.md](CONFIG.md) и совпадает с Windows.

## Программы в пресетах

- В поле «Программа» укажите путь к пакету **`.app`** (например `/Applications/Telegram.app`), к исполняемому файлу или URL. Кнопка «Обзор» выбирает `.app`. Путь может начинаться с `~/`.
- Запуск: `.app` - через `open -a`, URL и документы - через `open`, исполняемый файл - напрямую. Если заданы аргументы, приложение запускается как **новый экземпляр** (`open -n -a … --args …`), иначе macOS не передал бы им аргументы. Так работает, например, `--new-window https://…` для Chrome.
- «Запущена ли программа» определяется по имени процесса. Для `.app` оно берётся из `CFBundleExecutable` (Info.plist), поэтому обычно поле «Имя процесса» заполнять не нужно. Если приложение запускает процесс с другим именем, укажите его вручную (без учёта регистра, без расширения, например `Google Chrome`).
- Закрытие: мягкое - как Cmd+Q (`NSRunningApplication.terminate`), приложение может спросить о сохранении. По таймауту, если включено «завершить принудительно», - `forceTerminate`/`SIGKILL`. Поле «Команда закрытия» выполняется через `sh -c` вместо мягкого закрытия.
- Если список процессов (`ps`) получить не удалось, лаунчер ничего не закрывает и не запускает повторно уже отслеживаемые программы (запись об ошибке в журнале), а не считает, что «ничего не запущено».
- Защищённые процессы (не закрываются никогда): Finder, Dock, loginwindow, WindowServer, SystemUIServer, launchd, ControlCenter, NotificationCenter и т. п.
- Эмодзи в названиях пресетов и меню отображаются системой; в самом окне egui цветные эмодзи недоступны (как и в Windows-версии - только монохромные символы).

## Разрешения

macOS спросит их при первом использовании. Разрешения выдаются приложению в **Системные настройки → Конфиденциальность и безопасность**.

| Что нужно | Для чего | Где |
|---|---|---|
| **Автоматизация** (Automation) → «System Events» | `restart`, `shutdown` и `lock` через API | диалог появится при первой команде; потом - раздел «Автоматизация» |
| **Универсальный доступ** (Accessibility) | `lock` (приложение «нажимает» Ctrl+Cmd+Q) и, возможно, медиаклавиши | раздел «Универсальный доступ» |
| **Мониторинг ввода** (Input Monitoring), возможно | медиаклавиши `play_pause`/`next`/`prev` | раздел «Мониторинг ввода» |
| **Уведомления** | `POST /api/notify` | «Уведомления» → «Редактор скриптов» (Script Editor): уведомления отправляет `osascript` |
| **Входящие подключения** | доступ к API с iPhone/другого ПК | брандмауэр спросит при первом включении API; для работы только с этого Mac можно отказать |

Без нужного разрешения команда вернёт ошибку `500`, подробности - в журнале. Запасных вариантов нет: если блокировка через System Events не удалась (нет «Универсального доступа» или «Автоматизации»), API отвечает `500`, а не делает вид, что экран заблокирован (гашение дисплея сеанс не блокирует, если пароль запрашивается с задержкой). Медиаклавиши перед отправкой проверяют разрешение (`CGPreflightPostEventAccess`): без него тоже `500` с подсказкой про «Универсальный доступ» в журнале.

## Что не поддерживается или отличается

| Возможность | macOS |
|---|---|
| Гибернация (`power: hibernate`) | **не поддерживается**, API отвечает `501` |
| Медиаклавиша `stop` | **не поддерживается**, `501` (в macOS нет такой клавиши) |
| Сон (`sleep`) | `pmset sleepnow` |
| Перезагрузка, выключение | System Events, без принуждения: программы с несохранёнными данными могут задержать или отменить процесс |
| Блокировка экрана | Ctrl+Cmd+Q через System Events (нужен Универсальный доступ); без разрешения - `500`, запасного варианта нет |
| Минимальная версия | macOS 12 (определение имени процесса из `Info.plist` использует `plutil -extract`) |
| Громкость | `osascript` (`get volume settings`, `set volume`); если устройство вывода не управляется громкостью (часть HDMI/DisplayPort), `volume` в статусе будет `null` |
| Уведомления | Центр уведомлений от имени «Редактора скриптов» |
| «Свернулся в трей - завершить досрочно» | нет: окна чужих программ без Универсального доступа не перечислить, поэтому приложение закрывается само или по таймауту |
| `%ПЕРЕМЕННЫЕ%` в путях | работают (`%HOME%`), а также `~/` |
| Автозапуск | не через установщик: `preset-launcher autostart on` создаёт LaunchAgent (действует со следующего входа), `off` - удаляет. См. [CLI.md](CLI.md) |
| Dock | значок в Dock есть (`LSUIElement=false`); скрыть его пока нельзя |
| Консольные команды | `Preset Launcher.app/Contents/MacOS/preset-launcher status` и т. д., см. [CLI.md](CLI.md) |

Заготовленные при первом запуске пресеты на macOS содержат типичные программы из `/Applications` (отключены, если не найдены): настройте под себя.

## Что может пойти не так

- **Окно не открывается по клику на значок / команды из трея не работают при скрытом окне** - пришлите запись из журнала и версию macOS. Трей и горячие клавиши создаются на главном потоке, как требуют `tray-icon` и `global-hotkey`, но поведение eframe при скрытом окне на macOS проверено только по документации.
- **Ссылки и документы в пресете** (например `https://…`) открываются, но не отслеживаются и не закрываются при переключении, пока вы явно не укажете «Имя процесса». Автоматически имя выводится только для `.app` и исполняемых файлов.
- **Горячие клавиши не срабатывают** - в разделе «Мониторинг ввода»/«Универсальный доступ» может понадобиться разрешение для приложения.
- **«Приложение повреждено»** - снимите карантин: `xattr -dr com.apple.quarantine "/Applications/Preset Launcher.app"`.
