# Командная строка

Те же команды работают на Windows и macOS. Они **не запускают** переключение сами: обращаются к уже запущенному Preset Launcher по его локальному HTTP API (`127.0.0.1:<порт>`), поэтому в настройках приложения должен быть включён API (блок «Удалённое управление»). Порт и токен берутся из `config.toml` автоматически; токен не нужно вводить.

```
preset-launcher                          запустить приложение (окно/трей) - как обычно
preset-launcher switch <имя пресета>     переключить пресет
preset-launcher status [--json]          активный пресет, занят ли, громкость, версия
preset-launcher list [--json]            пресеты по одному в строке
preset-launcher autostart on|off|status  автозапуск при входе (только macOS)
preset-launcher --version | --help
```

Имя пресета можно писать без кавычек, если нет специальных символов: `preset-launcher switch Мои игры` равно `switch "Мои игры"`.

## Примеры

```
> preset-launcher list
Работа
Игры

> preset-launcher switch Игры
Переключение на «Игры» запущено

> preset-launcher status
Версия: 0.5.0
Активный пресет: Игры
Занят переключением: нет
Пресеты: Работа, Игры
Громкость: 40%
```

`switch` возвращает управление сразу после того, как приложение приняло команду (код `202`); само переключение идёт в фоне. Завершение смотрите в `status` (`Занят переключением`) или в журнале.

## Коды выхода

| Код | Значение |
|---|---|
| `0` | успех |
| `1` | ошибка: приложение не запущено или API выключен, неверный токен, неизвестный пресет, конфиг не найден или повреждён, сервер вернул ошибку |
| `2` | неверные аргументы |

Сообщения об ошибках пишутся в stderr, результат - в stdout. Пример для скрипта:

```sh
preset-launcher switch Работа || echo "не удалось переключить"
```

## Где запускать

**macOS.** Исполняемый файл лежит внутри приложения. Удобно сделать псевдоним (в `~/.zshrc`):

```sh
alias preset-launcher='"/Applications/Preset Launcher.app/Contents/MacOS/preset-launcher"'
```

Автозапуск: `preset-launcher autostart on` создаёт `~/Library/LaunchAgents/io.github.eg0rs.presetlauncher.plist` (приложение стартует свёрнутым при входе в систему), `off` удаляет файл, `status` показывает состояние. Действует со следующего входа.

**Windows.** Приложение собрано как оконное (`windows_subsystem = "windows"`), но в режиме CLI оно подключается к консоли родителя (`AttachConsole`), поэтому вывод виден в `cmd`, PowerShell и Windows Terminal. Исполняемый файл - `%LOCALAPPDATA%\Programs\Preset Launcher\preset-launcher.exe`; при желании добавьте этот каталог в `PATH`. Если запускать не из консоли (например, двойным кликом), вывода не будет. Автозапуск на Windows настраивает установщик, поэтому `autostart` там сообщает об ошибке.

## Аргументы и безопасность

- Без аргументов (или только с флагами `--autostart`, `--minimized`, `--preset ИМЯ`) запускается окно. Любая другая подкоманда или флаг, в том числе опечатка (`switsh`), - ошибка использования, код `2`, окно не открывается. Не-UTF-8 аргументы тоже дают код `2`.
- Ответ API ограничен 1 МБ, весь запрос - 20 с.
- CLI отправляет токен на `127.0.0.1:<порт из конфига>`. Подменить слушателя на этом порту может только локальный процесс того же пользователя, а он и так может прочитать `config.toml` с токеном, поэтому дополнительной защиты (например, проверки процесса-слушателя) нет.

## Другой каталог конфига и тестовый экземпляр

CLI использует тот же каталог, что и приложение: `%APPDATA%\PresetLauncher` (Windows), `~/Library/Application Support/PresetLauncher` (macOS) или каталог из `PRESET_LAUNCHER_DIR`. Это позволяет, например, держать отдельный тестовый экземпляр на другом порту:

```
# PowerShell
$env:PRESET_LAUNCHER_DIR = "C:\temp\pl-test"
preset-launcher status
```

CLI читает конфиг только на чтение: он ничего не создаёт и не меняет. Если конфига нет, команда подсказывает один раз запустить приложение.

## Служебная команда

`preset-launcher icon-png <размер> <файл.png>` записывает значок приложения в PNG. Её использует `scripts/bundle-macos.sh` для сборки `.icns`.
